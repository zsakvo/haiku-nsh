# 曲库、收藏、历史、统计与下载（F10 F11 F12 F13）

业务语义以参考版 SPEC F10–F13 与 §6 为准。

## 1. 本地曲库（haiku-library）

- 扫描：可以增删多个扫描根，手动扫描/重新扫描，显示进度并可取消；目录深度上限 32，多个扫描根之间去重；格式白名单与 haiku-audio 的可解码格式一一对应（MP3/FLAC/M4A/OGG Vorbis）。
- 读取标签、封面（提取到封面缓存目录）、歌词 sidecar；文件错误写入扫描报告。
- 身份：`source = "local"`，`id = 绝对路径`。
- 元数据覆盖是稀疏字段（只存被修改的字段）；重新扫描保留覆盖；文件暂时不在（例如移动硬盘未挂载）时不删除覆盖记录。
- 视图：歌曲、专辑、艺术家分组（主要艺术家与专辑艺术家分组规则同参考版）；支持搜索、排序和多选；批量播放、加入队列、加入歌单、编辑、刮削。
- 编辑：单曲和批量（只应用改动过的字段）、导入封面、重置；可选写回文件标签，写回前需要确认，错误逐个文件报告。
- 存储：扫描索引 `library/index.json`（可重建）；覆盖记录 `library/overrides.json`（权威数据）。

## 2. 刮削

- 候选来源：所有启用且实现了 `scrape` 的插件（可启停、可排序）；音乐来源（实现了 `search.track` 的平台来源）也可以配置为候选来源；歌词刮削单独配置。
- 任务：单首或批量；并发 4；单源 8 秒超时。打分达到 0.86 且领先第二名 0.08 时自动采用，0.55 以上进入待审，其余跳过。
- 审阅：查看候选、手动匹配、跳过、取消（已完成的结果保留）；自动匹配可以撤销。
- 语义：“只填补缺失字段”与“覆盖”两种模式；人工确认的结果持久化；未审阅的结果不会静默写回文件。
- D6：自动刮削不再需要会员。

## 3. 喜欢与歌单（haiku-store::collections）

- 权威数据：`playlists.loro`（与参考版格式兼容），由参考版 `playlist_core.rs` 迁移而来。缓存视图可以重建。
- 喜欢：`__liked__` 歌单，使用专用写入路径；跨来源的喜欢/取消喜欢；按加入时间排序；支持搜索、来源筛选、播放、批量管理。
- 用户歌单：创建、重命名、编辑描述、删除；跨来源加歌（去重）、移除、重排；歌单之间排序；网格或列表展示；封面由前几首曲目的封面合成。
- 收藏远端歌单：`kind = plugin`，id 为 `favorite:<sourceId>:<remotePlaylistId>`，存储 sourceId、playlistId、sourceLabel、cover、refreshedAt；不复制成可编辑的用户歌单。打开详情时优先刷新远端，完整翻页（PLUGIN_SDK §3.3）后原子更新，同时保留可用的离线快照；取消收藏不影响远端。
- 并发镜像取 `(refreshedAt, version)` 较大的一方，不对两个快照的 CRDT 曲目做并集。
- 每次修改后由服务负责落盘（参考版要求调用方显式 `save_to_disk`，本版收敛到服务内部，变更后防抖写盘，退出时冲刷）。
- 喜欢和收藏的状态通过事件推送给菜单栏、媒体中心和各列表。

## 4. 历史（haiku-store::history）

- 播放历史：跨来源身份去重，最多 500 条，按时间分组；支持搜索、筛选、删除单项、清空。
- 浏览歌单历史：独立记录，最多 100 条，按 kind/source/id 去重；保存需要认证的封面所需的 headers；trackCount 未知时留空。
- 搜索历史：去重，可删除单项，可清空。

## 5. 听歌统计（haiku-store::stats）

- 有效记录：单段真实播放至少 5 秒，最多保存 5000 条；排除暂停、seek 跳跃和异常间隔。
- 聚合：累计时长、次数、歌曲数、歌手数；日/月/年/全部范围；排行（按次数优先）；小时分布；日历热图；连续天数；里程碑（50/200/500/1000/2000/5000）。
- 远程：当登录了 Haiku 账号时，上传事件。`eventId = sha1(device|plugin|track|played|tz)`；meta/events 使用 revision 与 watermark；远程数据不回推；失败重试，防抖 12 秒，每 2 分钟拉取一次，后台失败时退避（最长 30 分钟）。
- 本地清除与云端清除分开操作，都需要确认。

## 6. 下载（haiku-services::downloads）

- 状态：queued / resolving / downloading / tagging / completed / failed / paused / canceled / missing，带进度。
- 单曲、歌单、批量下载；并发 1–5；暂停、继续、重试、取消、移除（仅记录或连同文件删除，需要确认）、清理已完成、失败重试。
- 重启时，进行中的任务回到 queued；`.part` 文件断点续传；重试间隔 2 秒、8 秒。
- 按音质调用 `streams` 取得候选（保留 headers）；以文件嗅探识别真实容器并修正扩展名；错误候选回退；断网后恢复；半成品不会被当作完整文件。
- 目录与命名：默认 `~/Music/Haiku`；文件名模板 `{artist} - {title}` 等；布局 flat / artist / artist-album / playlist / provider；过滤非法文件名并处理重名。
- 附加内容：封面高清或标清；封面与歌词分别可选 none / embed / sidecar / both；可选包含译文；写入标签；最后原子重命名为正式文件。
- 优先复用同音质的完整媒体缓存。
- 自动下载歌单：新增曲目自动下载；开启“跟随移除”时，只有同时满足“非手动下载”且“不再属于任何其他自动下载歌单”两个条件才删除。
- 更换目录：可选择移动、保留或取消；逐个文件报告失败；移动期间调度器暂停。
- 显示文件、打开所在目录、校验丢失文件。桌面端忽略“仅 Wi-Fi”限制。
- 下载任务的 key 为 `source + NUL + id`；底层每次尝试使用唯一 task id，避免过期事件影响重试。

## 7. 测试

- 本地扫描：临时目录中放入各种格式、编码、损坏文件和 sidecar 的 fixture；验证重新扫描保留覆盖。
- 刮削：使用假插件返回固定候选，覆盖阈值边界、取消、撤销。
- Loro：两个实例的冲突合并、重启后恢复、重复导入幂等；兼容参考版生成的 `playlists.loro`。
- 下载：本地 HTTP fixture（需要 headers、Range、MIME 错报、中途断开），验证文件内容、标签和 sidecar。
- 统计：模拟时钟驱动的有效播放判定与聚合。
