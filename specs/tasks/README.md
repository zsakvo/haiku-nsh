# 任务约定（所有任务默认适用）

执行者：Codex。审阅者：Claude。每个任务文件中的要求优先于本约定；任务未提到的，一律按本约定执行。

## 验证边界

- **只验证任务“验收”一节列出的项目**，每项跑一次即可。不要自行增加测试、探针、对照实验或审计。
- 测试写在项目里（`cargo test`、`*.test.tsx`、`nsh_testing`），作为可重复运行的回归测试；不写一次性的诊断脚本。确实需要临时排查时，排查完删除，不留在仓库或 `.artifacts/` 中。
- 不要用 lldb、AppleScript、辅助功能 API、CGEvent 等手段自动操作 GUI。界面交互由 Headless 测试覆盖；真实窗口只需要 `nsh run` 加一张截图。需要人工点击确认的，在汇报中列为“待人工确认”。
- 不要更换工具链重跑同一套命令（例如分别用 huacnlee/cargo 和 rustup cargo 各跑一遍）。
- 证据：每条命令保存一个日志到 `.artifacts/<任务号>/`，截图另存，不额外生成汇总 JSON 或 hash 清单。
- 某项验证失败时：先定位原因，最多尝试两种修复思路；仍不通过就记录现象和原因，然后停下汇报，不要无限扩展排查范围。

## 范围边界

- 只修改任务指定的文件和目录。`README.md` 只在任务要求时修改。`specs/` 中只能修改 `STATUS.md`。
- 不提交 git，不修改 Rex 会话或窗格，不修改参考项目、NSH 或依赖源码。
- 遇到任务没覆盖到的设计决策：选择最简单、可逆的做法，并在汇报中说明；影响架构的决策则停下来询问。

## 汇报

- `STATUS.md`：更新对应行，并追加一个日期小节，**不超过 40 行**，内容为：改动、命令与结果、证据路径、未覆盖的部分。
- 最终回复：改动的文件、验证结果（通过 / 失败 / 未覆盖）、问题与需要审阅者决定的事项。不要复述任务说明。
- 预计耗时明显超过任务规模时（例如小任务已经做了 30 分钟以上），先停下汇报进展。
